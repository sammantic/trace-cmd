# tracegen

A small C program that records boot-stage messages ("barebox started",
"kernel loaded", ...) and writes them either as a `trace.dat` file in
trace-cmd v6 format, readable by `trace-cmd report` and KernelShark, or as
a `trace.pftrace` file in Perfetto format, readable by
[ui.perfetto.dev](https://ui.perfetto.dev) and `trace_processor`.

Both writers are generated by hand, without libtraceevent, libtracefs or
protobuf. The recorder/writer (`trace.c`, `trace.h`) is separate from the
demo (`main.c`) so it can be reused elsewhere, for example inside barebox.

## Build and run

Requires a C11 compiler and make on a 64-bit little-endian Linux host.

```sh
make
./tracegen                  # writes trace.dat; use -o <file> for another path
trace-cmd report trace.dat
./tracegen -f perfetto      # writes trace.pftrace; open it in ui.perfetto.dev
```

The demo plays a fixed, made-up barebox boot sequence, sleeping a few
milliseconds between stages:

```
cpus=1
         barebox-1     [000]  3385.270156: task:                 barebox started
         barebox-1     [000]  3385.282228: task:                 board init done
         barebox-1     [000]  3385.285287: task:                 console ready
         barebox-1     [000]  3385.325379: task:                 mounting boot fs
         barebox-1     [000]  3385.333449: task:                 loading kernel
         barebox-1     [000]  3385.483615: task:                 kernel loaded
         barebox-1     [000]  3385.489702: task:                 loading device tree
         barebox-1     [000]  3385.514862: task:                 booting kernel
```

## Output formats

### trace-cmd v6 (`trace.dat`)

The binary format `trace-cmd record` produces. It embeds the header
descriptions and the event format the reader needs, so `trace-cmd report`
and KernelShark decode the custom `barebox:task` event without any prior
knowledge. Read it with:

```sh
trace-cmd report trace.dat
```

### Perfetto (`trace.pftrace`)

A stream of protobuf TracePackets, hand-encoded without libprotobuf and
validated with trace_processor. Each message appears twice on the
timeline:

- an instant (point) event on the track "barebox tasks", and
- a slice on "barebox stages" that lasts until the next message
  (Perfetto has no "slice with duration" event, only BEGIN/END pairs;
  the final slice gets duration 0 because the recorder never sees the
  boot finish).

Timestamps are CLOCK_MONOTONIC; a clock snapshot in the file relates
them to CLOCK_BOOTTIME and wall time, so the UI can show real times.
Open the file at [ui.perfetto.dev](https://ui.perfetto.dev) ("Open with
trace file"), or query it:

```sh
trace_processor_shell trace.pftrace "select name, dur from slice"
```

## Using the recorder in your own code

Compile `trace.c` into your program and include `trace.h`:

```c
#include "trace.h"

trace_add("barebox started");
/* ... do work ... */
trace_add("kernel loaded");
trace_write("trace.dat");
trace_write_perfetto("trace.pftrace");
trace_free();
```

| Function | What it does |
|----------|--------------|
| `trace_add(task)` | Append a message timestamped now (`CLOCK_MONOTONIC`). |
| `trace_add_at(ts_ns, task)` | Append a message with an explicit timestamp in nanoseconds. |
| `trace_write(path)` | Write all recorded messages to `path` as a trace.dat v6 file. |
| `trace_write_perfetto(path)` | Write all recorded messages to `path` as a Perfetto trace (protobuf TrackEvents). |
| `trace_free()` | Release all recorded messages. |
| `trace_count()` | Number of messages currently recorded. |

Functions that can fail return 0 on success and -1 with `errno` set.
Messages are kept in memory until a writer is called; both writers can be
called on the same list, and an empty list still produces a valid file
with no events.

## Tests

```sh
make test     # unit tests for the recorder, the page encoding and the protobuf encoding
make check    # runs tracegen in both formats and verifies the outputs
```

`make check` needs `trace-cmd` and `python3` installed; the Perfetto output
is decoded and cross-checked by `tests/check_pfetto.py`.

## Limitations

- The trace-cmd writer only writes the v6 format; there is no v7 or
  compression. The Perfetto writer emits plain uncompressed TracePackets
  (no interning; every event repeats its name and category).
- One CPU, and one event type (a single string per message).
- 64-bit little-endian hosts only, since integers are written in host byte order.
- The recorder keeps one global list and is not thread-safe.
- A single message is limited to roughly 4 KB by the trace.dat page
  encoding (the Perfetto writer has no such limit).
- The Perfetto writer assumes messages are valid UTF-8, which protobuf
  strings are expected to be.
